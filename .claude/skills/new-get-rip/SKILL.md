# Skill: helper-git-rep-manager

Этот скилл предназначен для эффективного управления, разработки и поддержки проекта `helper-git-rep`. Он предоставляет Claude Code контекст и инструкции по работе с архитектурой проекта, его запуску и публикации.

## 🎯 Цели скилла
- **Понимание структуры**: Быстрая навигация по агентной архитектуре «Оркестра».
- **Запуск и отладка**: Правильный старт сервиса и поиск ошибок в логах.
- **Развитие функционала**: Внесение изменений в логику агентов и Web UI.
- **Поддержка документации**: Актуализация README.md при изменении функций.
- **Публикация**: Подготовка локальных проектов к миграции на GitHub.

## 🏗 Архитектура проекта
Проект построен на базе многоагентной системы:
- **OrchestratorAgent**: Управляет жизненным циклом миграции (состояния: PENDING $\to$ ANALYZED $\to$ CLEANED $\to$ DOCUMENTED $\to$ COMPLETED).
- **ContentAgent**: Отвечает за интеллектуальный анализ проекта и генерацию README через LLM.
- **InfrastructureAgent**: Занимается технической частью: `.gitignore`, сканирование секретов и публикация через `gh` CLI.
- **LLMClient**: Универсальный интерфейс для взаимодействия с языковыми моделями.
- **StateManager**: Сохраняет состояние прогресса в `.helper_git_state.json`.

## 🛠 Операционное руководство

### 1. Запуск сервиса
Для запуска основного приложения используйте команду:
```bash
python main.py
```
Интерфейс доступен по адресу `http://127.0.0.1:5000`.

### 2. Работа с изменениями
- **Логика агентов**: Находится в `app/core/agents/`. При изменении одного агента обязательно проверяйте совместимость с `OrchestratorAgent`.
- **Web UI**: Шаблоны находятся в `app/web/templates/index.html`.
- **Конфигурация**: Настройки LLM и API находятся в папке `config/`.

### 3. Мониторинг и ошибки
При возникновении проблем в первую очередь проверяйте файл логов:
```bash
cat server.log
```

### 4. Обновление документации
При добавлении новых функций или изменении стека, обновите `README.md` в корне проекта. Описание должно оставаться профессиональным и ориентированным на портфолио.

### 5. Подготовка к публикации
Чтобы подготовить проект к переносу на GitHub:
1. Убедитесь, что все секреты вынесены в `.env` или `config/`.
2. Проверьте наличие `.gitignore`.
3. Используйте `gh` CLI для создания удаленного репозитория:
   `gh repo create <repo-name> --public --source=. --remote=origin --push`

## 📁 Ключевые пути
- `app/core/`: Ядро системы.
- `app/web/`: Фронтенд.
- `in-rep/`: Входящая очередь проектов.
- `passed-rep/`: Архив успешно перенесенных проектов.
- `CLAUDE.md`: Общие инструкции проекта.
